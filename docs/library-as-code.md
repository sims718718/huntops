# Task library as code

Team-built library tasks can be exported to YAML, kept in a git repository, reviewed in pull
requests, and imported back, so the repository is the source of truth for the library.
HuntOps never talks to the repository: a CI job or a person moves the files. Nothing here
needs network access or stores a credential.

## What is exported

Only **team-built** tasks (the "Team-built" source in the library). Reference tasks, the
curated and Sigma-derived entries, are regenerated by `seed_library` on every install and
are read-only, so they are never exported and an import can never overwrite them.

## File format

One YAML file per task. Export writes `<id>.yml`; import reads any `*.yml` or `*.yaml`
under the folder you point at, so you can organise folders however you like. Identity comes
from `id`, never from the file name or path.

```yaml
schema: huntops/library-task/v1
id: rare-service-install
title: Rare service installations (PsExec-style lateral movement)
hunting_tool: Splunk
techniques: [T1543.003, T1569.002]
data_sources: [WinEventLog:System]
sigma_rules: [6e4d1b0a-0000-0000-0000-000000000000]
query: |
  index=wineventlog ...
expected_positive: ...
expected_benign: ...
notes: ...
```

| Key | Required | Notes |
| --- | --- | --- |
| `schema` | yes | Must be exactly `huntops/library-task/v1`. |
| `id` | yes | Lower-case letters, digits, `.`, `_`, `-`; at most 100 characters. Shown on each task's page as its key. |
| `title` | yes | At most 300 characters. |
| `hunting_tool` | no | At most 100 characters. |
| `techniques` | no | ATT&CK ids. An id that is not installed is skipped with a warning. |
| `data_sources` | no | Names. A name that does not exist is created as a team-defined data source. |
| `sigma_rules` | no | Sigma `rule_id` UUIDs. An unknown id is skipped with a warning. |
| `query`, `expected_positive`, `expected_benign`, `notes` | no | Free text. |

Any other key is an error, so a typo is caught instead of silently dropped. Local-only
state (number, author, created date, provenance, dismissed data sources) is not exported.

## Import rules

- **The files win.** A task whose `id` already exists is overwritten from the file. A field
  left out of the file becomes empty, and the three lists are set exactly. The file's
  `sigma_rules` list is respected as written; ATT&CK auto-attach does not add rules to it.
- **Errors stop everything.** Every file is checked first. If any file has an error, nothing
  is written. Warnings (an uninstalled technique or Sigma rule) never block.
- **Nothing is deleted.** A task that is not in the files is left alone. Hunts that already
  used a task keep their own copy either way.
- Folders and files whose names start with `.` (`.git`, `.github`, `.gitlab-ci.yml`) are
  skipped, so you can point the command at a repository checkout.

## Command line

```
python manage.py export_library --dir library
python manage.py import_library --dir library --dry-run
python manage.py import_library --dir library
python manage.py import_library --file library/rare-service-install.yml
```

`export_library` is deterministic and never deletes files, so re-running it in a checkout
changes only the files whose tasks changed; remove a file yourself when you remove a task.
`import_library` exits non-zero on any error, which is what lets a pipeline gate on it.

In the app, the Task library page has **Export YAML** (a zip of every team-built task) and,
for users who can add and change library tasks, **Import YAML**, which shows a preview and
asks for confirmation. Uploads are limited to 1 MB and 500 files; use the command line for
larger libraries.

## Example pipelines

Run these on a runner that can reach your HuntOps deployment. The compose path and service
name are examples; adjust them to your install.

GitHub Actions, previewing on pull requests and importing on merge:

```yaml
name: library
on:
  pull_request: { paths: ["library/**"] }
  push: { branches: [main], paths: ["library/**"] }
jobs:
  library:
    runs-on: [self-hosted, huntops]
    steps:
      - uses: actions/checkout@v4
      - name: Preview
        if: github.event_name == 'pull_request'
        run: docker compose -f /opt/huntops/docker-compose.yml run --rm -v "$PWD/library:/library:ro" web python manage.py import_library --dir /library --dry-run
      - name: Import
        if: github.event_name == 'push'
        run: docker compose -f /opt/huntops/docker-compose.yml run --rm -v "$PWD/library:/library:ro" web python manage.py import_library --dir /library
```

GitLab CI:

```yaml
library-preview:
  tags: [huntops]
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  script:
    - docker compose -f /opt/huntops/docker-compose.yml run --rm -v "$CI_PROJECT_DIR/library:/library:ro" web python manage.py import_library --dir /library --dry-run

library-import:
  tags: [huntops]
  rules:
    - if: '$CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH'
  script:
    - docker compose -f /opt/huntops/docker-compose.yml run --rm -v "$CI_PROJECT_DIR/library:/library:ro" web python manage.py import_library --dir /library
```

To go the other way, run `export_library --dir library` from a checkout and commit the result.
